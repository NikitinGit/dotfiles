# Замена SSD на igor-desktop

Контекст для продолжения работы на другой машине.
Составлено 2026-10-26. Онлайн-версия: https://claude.ai/artifact/3CjDakphUgVZ8TcLK8LgZL

## Коротко

Накопитель **Patriot P400 1 ТБ** (серийный `P400DFBA22111410288`) неисправен: он
случайно пропадает с шины PCIe, остальной компьютер при этом продолжает работать.
Куплен **Kingston FURY Renegade 1 ТБ** (`SFYRSK1000G`, прошивка `EIFK51.2`,
серийный `50026B7283B26CAB`) на замену. Установлен в чипсетный слот, порт PCIe
`00:1b.4`, линия 16.0 GT/s x4 без ошибок. Надо перенести систему.

Эскалация отказов: 2 раза в неделю в июле–сентябре → ежедневно к середине октября
→ **6 аварийных перезагрузок за 26 октября** (самый долгий сеанс 2 часа, самый
короткий 13 минут).

## Доказательства

- `BTRFS error (device nvme0n1p2 state EA): bdev <missing disk> errs: wr 18, rd 579`
- `systemd[1]: Failed to spawn executor: Input/output error`
- `[!!!!!!] Failed to execute shutdown binary` + отказ размонтировать всё
- Во время зависания работал голосовой чат Steam, часы шли дальше последней записи
  в журнале, скриншотилка открывалась но не сохраняла файл → живы CPU, RAM, GPU,
  сеть, звук; мёртв только диск
- Процессы уходят в D-state, поэтому Force Quit не срабатывает

**SMART обманчив**: PASSED, износ 1 %, резерв 100 %, ноль ошибок носителя.
Растёт только Unsafe Shutdowns (313 → 316 за 12 дней). Счётчик наработки
занижает в 7 раз (16 ч против 107 фактических) — сырая прошивка.

Прошивка V1.4A — последняя. В каталоге Patriot прошивок для P400 нет вообще,
модель снята с производства.

## Что переносить

Система на **disko + preservation (impermanence)**: `@root` стирается при каждой
загрузке, всё переживающее перезагрузку перечислено явно в `storage.nix`.

| Подтом | Что внутри | Копировать |
| --- | --- | --- |
| `@home` | 344 ГБ, из них 281 ГБ — файлы игр в `Steam/steamapps` | Да, без игр и кэша — ~40 ГБ |
| `@persist` | Тома Docker с MySQL, настройки сети, ключи SSH, machine-id, логи | Да, целиком |
| `@root` | Стирается при загрузке | Нет |
| `@nix`, `/boot` | Пересобираются из flake | Нет |

## План

Делается **из работающей системы**, оба диска подключены одновременно.
Загрузочная флешка записана и держится рядом как аварийное средство, но в
обычном сценарии не нужна. Почему так можно — см. «Критично» ниже.

0. Отправить конфиг на GitHub. Репозиторий публичный, при аварии клонируется
   без ключей.

1. Выключить компьютер, поставить новый диск в **свободный слот M.2**.
   Старый Patriot стоит в верхнем слоте M.2_1 у радиатора процессора
   (порт PCIe `00:06.0`) — его не трогаем, с него копируем.

   У версии `SFYRSK1000G` свой радиатор, поэтому под радиаторы платы она не
   влезает: нужен слот, над которым радиатора нет. Платный радиатор ей и не
   требуется.

2. Включить **в обычную систему**, не с флешки. В BIOS заходить не нужно.

3. Проверить, что диск виден и контакт полный:

       lsblk -d -o NAME,SIZE,MODEL,SERIAL
       K=/sys/bus/pci/devices/0000:05:00.0   # адрес нового диска
       cat $K/current_link_speed $K/current_link_width   # ждём 16.0 GT/s и 4
       grep -v ' 0$' $K/aer_dev_correctable               # ждём пусто

   Урезанная линия (x1/x2) или ошибки AER означают плохую посадку в слоте —
   тогда сначала переставить диск, а не продолжать.

4. **Имена устройств меняются при добавлении диска.** После установки Kingston
   стало так: `nvme0n1` — новый диск, `nvme1n1` — Patriot с системой. Поэтому в
   конфиге адресация только по серийному номеру.

5. Правки в `hosts/igor-desktop/storage.nix` (сделаны):

   | Было | Стало |
   | --- | --- |
   | `disk.main` | `disk.kingston` |
   | `device = "/dev/nvme0n1"` | `device = "/dev/disk/by-id/nvme-KINGSTON_SFYRSK1000G_50026B7283B26CAB"` |
   | `disk-main-root` в службе `rollback` | `disk-kingston-root` (3 места, включая имена unit-ов с `\x2d`) |

   Проверить, что метки разъехались:

       nix eval --raw .#nixosConfigurations.igor-desktop.config.fileSystems.\"/\".device

   Должно вернуть `/dev/disk/by-partlabel/disk-kingston-root`.

6. Разметить новый диск. **Единственный необратимый шаг**, перед запуском
   сверить серийный номер в конфиге:

       nix run github:nix-community/disko -- --mode destroy,format,mount \
           --flake /home/igor/dotfiles#igor-desktop

   Подтома нового диска окажутся в `/mnt`. Patriot не затрагивается, система
   продолжает работать.

7. Скопировать данные (около 50 ГБ: `/home` 46 ГБ + `/persist` 4 ГБ):

       rsync -aHAX --partial --info=progress2 \
           --exclude='igor/.local/share/Steam/steamapps' \
           --exclude='igor/.cache' \
           --exclude='igor/java_error_in_idea.hprof' \
           /home/ /mnt/home/
       rsync -aHAX --partial --info=progress2 /persist/ /mnt/persist/

   Исключается только `steamapps` — сами файлы игр. Каталоги `userdata`
   (сохранения) и `config` (вход в аккаунт) копируются: они маленькие, но
   потерять их обидно. Также пропускаем `.cache` (20 ГБ, пересоздаётся сам) и
   дамп падения IntelliJ на 2,8 ГБ.

   Всё остальное переносится как есть: ключи SSH из `~/.ssh`, история команд
   `~/.zsh_history`, настройки IDE, проекты, базы MySQL в томах Docker.

   Если старый диск отвалится посреди копирования — перезагрузиться, повторить
   шаг 6 с `--mode mount` (**не** `destroy`) и шаг 7. `rsync` досинхронизирует
   остаток благодаря `--partial`.

8. Установить систему:

       nixos-install --root /mnt --flake /home/igor/dotfiles#igor-desktop --no-root-passwd

9. Выключить, вынуть Patriot. **Не выбрасывать — нужен для гарантии в DNS.**
   Заодно дожать защёлку нового диска или вкрутить винт M2x3, раз корпус открыт.

10. Включить. Если не загрузится сразу — `Del` при включении, раздел **Boot**,
    поставить Kingston первым. Проверить файлы, базы в Docker, сеть, вход по SSH.

11. Закоммитить, откатить временные правки (таблица ниже), скачать игры Steam
    заново.

### Критично

**Опасность была в одинаковых метках разделов, и она снята правкой конфига.**

Вся система адресуется не по именам устройств, а по **меткам разделов**: в
`/etc/fstab` все строки вида `/dev/disk/by-partlabel/disk-main-root`, и служба
`rollback` в initrd обращается по той же метке. disko присваивает метки из
конфига, то есть новый диск получил бы **точно такие же** метки, что у старого.
Два раздела с одной меткой — и симлинк указывает на тот, который udev увидел
первым, то есть на случайный.

Именно поэтому запись `disk.main` переименована в `disk.kingston`. Теперь у
старого диска метки `disk-main-*`, у нового `disk-kingston-*`, пересечения нет
ни во время переноса, ни после. Проверяется так:

    lsblk -o NAME,PARTLABEL /dev/nvme1n1   # старый: disk-main-boot, disk-main-root
    lsblk -o NAME,PARTLABEL /dev/nvme0n1   # новый:  disk-kingston-boot, disk-kingston-root

Из этого следуют два полезных вывода:

- перенос можно делать **из работающей системы**, live-USB не обязателен;
- **перезагружаться посреди переноса безопасно** — каждая система найдёт свои
  разделы по своим меткам. Это важно, потому что старый диск отваливается
  каждые несколько часов.

Вторая опасность — жёстко прописанный `device = "/dev/nvme0n1"`. Порядок имён
при двух дисках не гарантирован, и он действительно поменялся: после установки
Kingston имя `nvme0n1` перешло к новому диску. Запуск disko с таким путём мог
отформатировать рабочий диск. Снято переходом на `/dev/disk/by-id/`.

## Временные правки к откату

Все помечены комментарием `ВРЕМЕННО` в `hosts/igor-desktop/default.nix`.
Убирать по одной, после нескольких дней работы нового диска без сбоев.

| Что | Зачем | После замены |
| --- | --- | --- |
| `systemd.services.hw-sampler` | Снятие температур/PSI каждые 30 с | Удалить |
| `systemd.services.cpu-power-limit` | Лимит RAPL 95/110 Вт | Удалить |
| `systemd.services.gpu-power-limit` | Лимит GPU 120 Вт | Удалить |
| `systemd-boot.memtest86.enable` | Пункт memtest в меню | Оставить до прогона |
| `pcie_aspm=off` | Энергосбережение шины | Удалить |
| `intel_idle.max_cstate=1` | Запрет глубокого сна CPU | Удалить — растёт потребление |
| `nvme_core.default_ps_max_latency_us=0` | APST | Удалить |
| `nvme.max_host_mem_size_mb=0` | HMB | Удалить — у FURY своя DRAM |
| `oops=panic`, `softlockup_panic=1`, `nmi_watchdog=panic`, `panic=0` | Принудительная паника ядра | Удалить все четыре |

Остаются насовсем: `nct6775`, `acpi_enforce_resources=lax`, `kernel.sysrq = 1`.

В BIOS выключен XMP — включать обратно отдельным шагом, не в один день с переездом.

### Грабли с sudo

В интерактивной оболочке `/run/current-system/sw/bin` идёт раньше
`/run/wrappers/bin`, выбирается `sudo` без setuid:
`sudo must be owned by uid 0 and have the setuid bit set`.
Лечится новым окном терминала или префиксом `PATH=/run/wrappers/bin:$PATH`.
