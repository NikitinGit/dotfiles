# Замена SSD на igor-desktop

Контекст для продолжения работы на другой машине.
Составлено 2026-10-26. Онлайн-версия: https://claude.ai/artifact/3CjDakphUgVZ8TcLK8LgZL

## Коротко

Накопитель **Patriot P400 1 ТБ** (серийный `P400DFBA22111410288`) неисправен: он
случайно пропадает с шины PCIe, остальной компьютер при этом продолжает работать.
Куплен **Kingston FURY** на замену. Надо перенести систему.

Эскалация отказов: 2 раза в неделю в июле–сентябре → ежедневно к середине октября
→ **6 аварийных перезагрузок за 26 октября** (самый долгий сеанс 2 часа, самый
короткий 13 минут).

## Доказательства

- `BTRFS error (device nvme0n1p2 state EA): bdev <missing disk> errs: wr 18, rd 579`
- `systemd[1]: Failed to spawn executor: Input/output error`
- `[!!!!!!] Failed to execute shutdown binary` + отказ размонтировать всё
- Во время зависания работал голосовой чат Steam, часы шли дальше последней записи
  в журнале, скриншотилка открывалась но не сохраняла файл → живы CPU, RAM, GPU,
  сеть, звук; мёртв только диск
- Процессы уходят в D-state, поэтому Force Quit не срабатывает

**SMART обманчив**: PASSED, износ 1 %, резерв 100 %, ноль ошибок носителя.
Растёт только Unsafe Shutdowns (313 → 316 за 12 дней). Счётчик наработки
занижает в 7 раз (16 ч против 107 фактических) — сырая прошивка.

Прошивка V1.4A — последняя. В каталоге Patriot прошивок для P400 нет вообще,
модель снята с производства.

## Что переносить

Система на **disko + preservation (impermanence)**: `@root` стирается при каждой
загрузке, всё переживающее перезагрузку перечислено явно в `storage.nix`.

| Подтом | Что внутри | Копировать |
| --- | --- | --- |
| `@home` | 344 ГБ, из них 281 ГБ — файлы игр в `Steam/steamapps` | Да, без игр и кэша — ~40 ГБ |
| `@persist` | Тома Docker с MySQL, настройки сети, ключи SSH, machine-id, логи | Да, целиком |
| `@root` | Стирается при загрузке | Нет |
| `@nix`, `/boot` | Пересобираются из flake | Нет |

## План

Делается **с загрузочной флешки, за один сеанс**, без перезагрузок в
установленную систему. Почему именно так — см. «Критично» ниже.

0. Отправить конфиг на GitHub (сделано 2026-10-26, коммит `75ce9bf`).
   Репозиторий публичный, на этапе установки клонируется без ключей.

1. На ноутбуке записать установочный образ NixOS на флешку (Rufus, Ventoy или
   balenaEtcher). Образ: https://nixos.org/download — minimal или graphical,
   разницы для этой задачи нет.

2. Выключить компьютер, поставить новый диск в **любой свободный слот M.2 ниже**
   (на чипсете). Старый Patriot стоит в верхнем слоте M.2_1 у радиатора
   процессора (порт PCIe `00:06.0`) — его не трогаем, с него будем копировать.

3. Включить, нажать `F8` (меню загрузки ASUS), выбрать флешку.

4. В live-системе поднять сеть и получить конфиг:

       sudo -i
       # проводная сеть обычно поднимается сама; проверить: ping -c2 github.com
       nix-shell -p git
       git clone https://github.com/NikitinGit/dotfiles /tmp/dotfiles

5. Узнать стабильное имя нового диска. Старый опознаётся по серийному номеру
   `P400DFBA22111410288`:

       ls -l /dev/disk/by-id/ | grep -i nvme

6. **Поменять `device` в `/tmp/dotfiles/hosts/igor-desktop/storage.nix`** с
   `/dev/nvme0n1` на `/dev/disk/by-id/nvme-KINGSTON_…` (имя из шага 5).

7. Разметить новый диск (команда разрушающая — сверить строку из шага 6):

       nix run github:nix-community/disko -- --mode destroy,format,mount --flake /tmp/dotfiles#igor-desktop

   Подтома нового диска окажутся смонтированы в `/mnt`.

8. Примонтировать старый диск только на чтение и скопировать данные.
   Подставить реальное имя старого раздела (`nvme1n1p2` или `nvme0n1p2`):

       mkdir -p /old
       mount -o ro,subvol=@home /dev/disk/by-id/nvme-Patriot_M.2_P400_1024GB_P400DFBA22111410288-part2 /old
       rsync -aHAX --partial --info=progress2 \
           --exclude='igor/.local/share/Steam/steamapps' \
           --exclude='igor/.cache' \
           --exclude='igor/java_error_in_idea.hprof' \
           /old/ /mnt/home/
       umount /old
       mount -o ro,subvol=@persist /dev/disk/by-id/nvme-Patriot_M.2_P400_1024GB_P400DFBA22111410288-part2 /old
       rsync -aHAX --partial --info=progress2 /old/ /mnt/persist/
       umount /old

   Исключается только `steamapps` — сами файлы игр. Каталоги `userdata`
   (сохранения) и `config` (вход в аккаунт) копируются: они маленькие, но
   потерять их обидно. Также пропускаем `.cache` (20 ГБ, пересоздаётся сам) и
   дамп падения IntelliJ на 2,8 ГБ.

   Всё остальное в `/home` переносится как есть: ключи SSH из `~/.ssh`,
   история команд `~/.zsh_history`, настройки IDE, проекты.

   Если старый диск отвалится посреди копирования — перезагрузиться с флешки и
   повторить шаги 7 (только `--mode mount`, не `destroy`) и 8. `rsync`
   досинхронизирует остаток.

9. Установить систему:

       nixos-install --flake /tmp/dotfiles#igor-desktop --no-root-passwd

10. **Выключиться и вынуть старый диск, не загружаясь в новую систему.**

11. Включить. В BIOS при необходимости поставить новый диск первым в порядке
    загрузки. Проверить файлы, базы в Docker, сеть, вход по SSH.

12. Закоммитить правку `storage.nix` (адрес `by-id` оставить, он надёжнее
    `/dev/nvme0n1`). Скачать игры Steam заново, откатить временные правки.

### Критично

**Две опасности, обе из-за того, что дисков временно два.**

Первая: в `storage.nix` диск задан жёстко как `device = "/dev/nvme0n1"`.
Порядок имён `nvme0n1`/`nvme1n1` при двух дисках **не гарантирован** — он
зависит от того, кто быстрее ответит при загрузке. Запуск disko с этим путём
может отформатировать рабочий диск. Шаг 6 обязателен и делается до шага 7.

Вторая, менее очевидная: вся система адресуется не по именам устройств, а по
**меткам разделов**. В `/etc/fstab` все строки вида
`/dev/disk/by-partlabel/disk-main-root`, и служба `rollback` в initrd тоже
обращается по этой метке. disko присвоит новому диску **точно такие же метки**
(`disk-main-boot`, `disk-main-root`), потому что они заданы в конфиге. После
разметки в системе окажется два раздела с одинаковой меткой, и симлинк
`/dev/disk/by-partlabel/disk-main-root` будет указывать на тот, который udev
увидел первым — то есть на случайный.

Поэтому: **между разметкой нового диска и извлечением старого нельзя
загружаться в установленную систему**. Внутри одного сеанса с флешки проблемы
нет — там всё монтируется явно, вручную. Отсюда и выбор в пользу live-USB, а не
установки из работающей системы.

## Временные правки к откату

Все помечены комментарием `ВРЕМЕННО` в `hosts/igor-desktop/default.nix`.
Убирать по одной, после нескольких дней работы нового диска без сбоев.

| Что | Зачем | После замены |
| --- | --- | --- |
| `systemd.services.hw-sampler` | Снятие температур/PSI каждые 30 с | Удалить |
| `systemd.services.cpu-power-limit` | Лимит RAPL 95/110 Вт | Удалить |
| `systemd.services.gpu-power-limit` | Лимит GPU 120 Вт | Удалить |
| `systemd-boot.memtest86.enable` | Пункт memtest в меню | Оставить до прогона |
| `pcie_aspm=off` | Энергосбережение шины | Удалить |
| `intel_idle.max_cstate=1` | Запрет глубокого сна CPU | Удалить — растёт потребление |
| `nvme_core.default_ps_max_latency_us=0` | APST | Удалить |
| `nvme.max_host_mem_size_mb=0` | HMB | Удалить — у FURY своя DRAM |
| `oops=panic`, `softlockup_panic=1`, `nmi_watchdog=panic`, `panic=0` | Принудительная паника ядра | Удалить все четыре |

Остаются насовсем: `nct6775`, `acpi_enforce_resources=lax`, `kernel.sysrq = 1`.

В BIOS выключен XMP — включать обратно отдельным шагом, не в один день с переездом.

### Грабли с sudo

В интерактивной оболочке `/run/current-system/sw/bin` идёт раньше
`/run/wrappers/bin`, выбирается `sudo` без setuid:
`sudo must be owned by uid 0 and have the setuid bit set`.
Лечится новым окном терминала или префиксом `PATH=/run/wrappers/bin:$PATH`.
